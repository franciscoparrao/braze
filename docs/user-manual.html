Manual de usuario

Referencia completa de braze — todo flag, todo comando, toda variable de configuración. Pensado para buscar (Ctrl+F), no para leer de corrido.

commit de referencia: 69a4527 proyecto: /home/franciscoparrao/proyectos/braze ver también: docs/usability-testing-guide.html, docs/self-improvement-guide.html

§Instalación

braze es un target del workspace (crates/braze-cli, binario braze), no algo instalado a nivel del sistema. Dos formas de tenerlo disponible:

Sin instalar nada

cargo run -p braze-cli --release -- chat --tui

Instalado en ~/.cargo/bin (recomendado para uso frecuente)

cargo install --path crates/braze-cli --locked

Después de esto, braze queda disponible directo. Si el código cambia, hay que repetir el cargo install.

§Inicio rápido

Sin ningún archivo de configuración, braze apunta a Ollama local (http://localhost:11434, modelo llama3.1) por defecto — no gasta ninguna API sin que lo pidas explícitamente:

braze chat --tui

Contra un backend en la nube, con la key ya en config.json (ver § Configuración):

braze chat --tui --backend anthropic --model claude-opus-4-6-20260805

Un solo prompt, sin sesión interactiva:

braze run "lee main.rs y dime qué hace"

§braze chat

Sesión interactiva — lee líneas de stdin hasta EOF (Ctrl+D) o las palabras literales exit/quit. Con --tui, usa la interfaz de terminal completa en su lugar.

--resume <session-id>
Retoma una sesión existente por id en vez de empezar una nueva. El id se imprime al arrancar cualquier chat/run. Un id que no existe no es un error — arranca una sesión nueva vacía con un aviso a stderr.
--backend <anthropic|ollama|openrouter>
Sobreescribe el backend configurado por defecto para esta corrida.
--model <nombre>
Sobreescribe el modelo configurado para esta corrida.
--ollama-url <url>
Sobreescribe la URL base del servidor Ollama — p.ej. --ollama-url http://192.168.1.8:11434 para usar un nodo LAN en vez de localhost. Pisa el archivo de config y BRAZE_OLLAMA_BASE_URL.
--tui
Usa la interfaz de terminal completa en vez del loop de texto plano por stdin/stdout. Opt-in. Las acciones irreversibles muestran un overlay de aprobación real (y/n) con teclado.
--theme <dark|light|high-contrast>
Preset de color para --tui (default dark). Ignorado sin --tui.
--planner <backend[:modelo]>
Activa el split planificador/ejecutor: un modelo más fuerte planea una vez por turno, el backend primario ejecuta. Ej.: --planner openrouter:deepseek/deepseek-v4-flash. Sobreescribe planner_backend/planner_model.
--lead <backend[:modelo]>
Activa la escalación reactiva lead/worker (estilo Goose): el lead abre la sesión y vuelve cuando el backend primario encadena observaciones fallidas. Compone con --planner (proactivo vs. reactivo). Sobreescribe lead_backend/lead_model.
--supervised
Fuerza toda acción a pasar por confirmación interactiva, sin importar lo que diría el clasificador por defecto — ni siquiera un write_file dentro del propio proyecto se aplica sin preguntar. Ver § Modelo de permisos y docs/self-improvement-guide.html.

§braze run <prompt>

Un solo prompt, una sola respuesta, sale. Mismos flags que chat excepto --resume, --tui y --theme (no aplican a una corrida de un solo turno).

prompt
Posicional, obligatorio. El texto a enviar.
--backend <anthropic|ollama|openrouter>
Igual que chat --backend.
--model <nombre>
Igual que chat --model.
--ollama-url <url>
Igual que chat --ollama-url.
--planner <backend[:modelo]>
Igual que chat --planner.
--lead <backend[:modelo]>
Igual que chat --lead.
--supervised
Igual que chat --supervised.

--help/-h y --version/-V están disponibles en la raíz y en cada subcomando (provistos por clap, sin lógica propia). No hay más subcomandos que chat y run.

§Slash commands (solo --tui)

ComandoQué hace
/helpMuestra los atajos de teclado y comandos disponibles.
/modelAbre un picker interactivo con los backends configurados más los modelos instalados en el servidor Ollama en uso.
/model <backend[:modelo]>Cambia de modelo directo, sin el picker — p.ej. /model ollama:qwen2.5:3b. Reconstruye el motor con el mismo session id, sin perder la conversación.

El match de / es por prefijo (no substring) mientras escribís, para autocompletar.

Lo que no existe (a propósito)

  • No hay scroll propio de braze (ni PageUp/PageDown ni mouse wheel manejados por la TUI) — la TUI corre sin pantalla alternativa a propósito, así que todo lo ya finalizado queda en el scrollback nativo de tu terminal. Para ver algo que pasó hace rato, usá el scroll de tu propio emulador de terminal (mouse wheel, o el modo copia de tmux/screen si corrés adentro de uno), no un atajo de braze.
  • No hay historial de mensajes por flechas — ↑/↓ con el composer vacío y sin popup abierto no recuperan un mensaje anterior (a diferencia de una shell). La única forma de volver a un mensaje previo es Esc Esc (backtrack).
  • Sin soporte de mouse más allá de lo que tu terminal haga por su cuenta — braze no captura clicks ni selección con el mouse.

§config.json

Ubicación: $XDG_CONFIG_HOME/braze/config.json, si no ~/.config/braze/config.json. Si no existe, o ninguna de las dos variables de entorno está seteada, braze simplemente omite esta capa (no es un error). Un JSON inválido sí es un error de arranque; una clave desconocida solo genera un warning y se ignora.

Precedencia (de menor a mayor prioridad): defaults hardcodeados → config.json → variables de entorno BRAZE_* → flags de línea de comando.

{
  "default_backend": "ollama",
  "ollama_base_url": "http://192.168.1.8:11434",
  "ollama_model": "qwen3.5-coder:latest",
  "anthropic_api_key": "sk-ant-...",
  "anthropic_model": "claude-opus-4-6-20260805",
  "openrouter_api_key": "sk-or-...",
  "openrouter_model": "deepseek/deepseek-v4-flash",
  "max_tokens": 4096,
  "tui_theme": "dark",
  "mcp_servers": [
    {"name": "mi-servidor", "command": "npx", "args": ["-y", "algun-mcp-server"]}
  ]
}

§Servidores MCP

Se configuran únicamente en config.json (no hay flag ni variable de entorno), como un array bajo mcp_servers:

{
  "mcp_servers": [
    {"name": "filesystem", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/ruta"]}
  ]
}

Cada entrada: name (string, usado para namespacing mcp__<name>__<tool> — dos entradas con el mismo nombre generan un warning de colisión), command (string, el ejecutable), args (array de strings, default []). Un servidor caído o mal configurado no aborta el arranque de braze — queda simplemente no disponible, con un warning.

§Backends soportados

BackendRequiereModelo por defectoNotas
anthropic API key + modelo ninguno — error de arranque si falta Sin anthropic_model/--model, braze rehúsa adivinar.
ollama nada llama3.1 Sin API key. Único backend con presupuesto de contexto calculado automáticamente (ollama_num_ctx).
openrouter API key + modelo ninguno — error de arranque si falta No calcula presupuesto de contexto del lado cliente — un modelo con ventana chica puede truncar/fallar server-side sin aviso previo.

§Herramientas del modelo

Seis tools, siempre disponibles (más las que agregue cada servidor MCP configurado). Todo resultado de cualquier tool se trunca a 8000 bytes antes de volver al modelo, con un aviso a narrower la consulta si se cortó.

read_file

path string, requerido
Ruta absoluta o relativa al directorio de trabajo.
offset integer, opcional
Línea desde la que empezar a leer, 1-indexado. 0 se rechaza explícitamente.
limit integer, opcional
Máximo de líneas a devolver desde offset.

Archivos de hasta 200 líneas se devuelven completos sin paginar. Más allá de eso, cada página trae un encabezado [lines X-Y of N] y, si queda más contenido, un pie indicando el próximo offset a usar.

write_file

path string, requerido
Ruta del archivo a crear o sobreescribir.
content string, requerido
Contenido completo del archivo.

Si el archivo previo era considerablemente más grande que el contenido nuevo, agrega una advertencia sobre posible pérdida de contenido por sobrescritura parcial.

edit_file

path string, requerido
Archivo a editar (debe existir).
old_string string, requerido
Texto a reemplazar — debe aparecer exactamente una vez.
new_string string, requerido
Texto de reemplazo.

Escalera de matching: (1) substring exacto — siempre gana si es único; (2) línea completa ignorando espacios finales; (3) línea completa ignorando espacios al inicio y al final, reindentando según la indentación real del archivo. Ambigüedad (2+ ocurrencias) o ausencia total del texto es un error explícito, nunca una suposición.

shell_exec

command array de strings, requerido, mínimo 1 elemento
Estilo argv: command[0] es el programa, el resto son sus argumentos. Nunca un string de shell crudo.

Un código de salida distinto de 0 no es un error de la tool — vuelve como JSON con exit_code/stdout/stderr. Sin timeout propio (corre hasta terminar); sí puede ser cancelado si la tarea que lo espera se aborta.

grep

pattern string, requerido
Texto o expresión a buscar.
path string, opcional
Default ..
regex bool, opcional
Default false (substring literal). true usa expresiones regulares POSIX extendidas.

Sin coincidencias no es un error — devuelve "no matches found".

glob

pattern string, requerido
Patrón de nombre de archivo (p.ej. *.rs).
path string, opcional
Default ..

Sin coincidencias devuelve "no files matched", no un error.

Guardrail post-edición

Tras un write_file/edit_file exitoso sobre un archivo .rs dentro de un proyecto Cargo, braze corre cargo check automáticamente (timeout 60s) y agrega el feedback al resultado de la tool si falla — el modelo ve el error de compilación en el mismo turno, sin que se lo tengas que pegar vos. Desactivable con disable_post_edit_check.

§Modelo de permisos

Cada acción (escribir, borrar, correr un comando) se clasifica Reversible o Irreversible antes de ejecutarse. Reversible pasa sin preguntar; Irreversible muestra un overlay/prompt y espera tu aprobación.

  • Dentro del directorio de trabajo: escrituras y borrados son Reversible.
  • Fuera del directorio de trabajo: siempre Irreversible, sin excepción.
  • Comandos de shell: default-deny. Solo un conjunto explícito de comandos de solo lectura (ls, pwd, wc, whoami, date, which, más cat/head/tail/grep/find/diff/git/env con validación adicional de argumentos) es Reversible. Todo lo demás — mv, dd, curl, chmod, un rm sin flags, cualquier programa no reconocido — es Irreversible.
  • Tool de un servidor MCP: siempre Irreversible (código de terceros sin auditar).

Con --supervised, todo lo anterior se ignora — cada acción, sin excepción, pasa por confirmación. Ver docs/self-improvement-guide.html para el caso de uso pensado para este modo.

§Sesiones

Cada sesión es un archivo <session-dir>/<uuid>.jsonl — una línea JSON por evento, append-only. No existe un comando braze sessions list; para eso está tools/braze_sessions.py:

python3 tools/braze_sessions.py list
python3 tools/braze_sessions.py show <session-id> [--full]

--resume <id> retoma una sesión existente, incluyendo permisos ya aprobados (no se vuelven a preguntar).

§Observabilidad

Toda traza va a stderr (nunca se mezcla con la conversación en stdout), gateada por RUST_LOG:

RUST_LOG=braze_engine=info braze chat --tui
RUST_LOG=debug braze run "..."

braze_engine=info expone cuándo se activan las palancas de confiabilidad (rescate textual de tool calls, compactación de contexto) sin inundar la salida.

§Errores y códigos de salida

Solo dos códigos de salida posibles: 0 (éxito) o 1 (cualquier error de arranque). Un turno individual que falla dentro de una sesión chat ya en curso no mata el proceso — se imprime "braze: turn failed: ..." y la sesión sigue.

SituaciónMensaje
Falta la API key de Anthropicfalta ANTHROPIC_API_KEY (config file, BRAZE_ANTHROPIC_API_KEY, o --backend anthropic sin key configurada)
Falta el modelo de Anthropicfalta --model o BRAZE_ANTHROPIC_MODEL para el backend anthropic
Falta la API key de OpenRouterfalta OPENROUTER_API_KEY (config file, BRAZE_OPENROUTER_API_KEY, o --backend openrouter sin key configurada)
Backend desconocidounknown backend '{other}' (expected 'anthropic', 'ollama', or 'openrouter')
Tema de TUI desconocidotema de TUI desconocido: '{tema}' (esperado 'dark', 'light', o 'high-contrast')
--resume con un id que no existebraze: aviso: no se encontró la sesión {id} — iniciando una nueva sesión vacía (no es fatal)
